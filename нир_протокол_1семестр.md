### Суть исследования

Выбор «какая LLM какому агенту на какой подзадаче» формализуется как **задача справедливого дележа** (fair division) с теоретико-игровыми критериями. Ресурс — пакеты «модель + токены» равной стоимости.

### Научная новизна

Объединение трёх областей, которые в рассмотренном корпусе литературы изучались раздельно: мультиагентные LLM-системы, маршрутизация задач и формальные модели справедливого распределения.

### Обзор аналогов 

| Работа | Что делает | Чего не хватает |
|---|---|---|
| Hosseini & Khanna (2025), *Distributive Fairness in LLM* | LLM отклоняются от человеческих критериев справедливости (EQ, EF, Rawlsian Maximin), предпочитая утилитарные решения | централизованный сеттинг, нет мультиагентной архитектуры |
| Binkytė (2025), *Interactional Fairness in LLM-MAS* | тон и качество объяснений влияют на принятие решений агентами | нет маршрутизации задач и вычислительных ресурсов |
| Vallinder & Hughes (2025) и др. о социальных дилеммах | кооперация зависит от архитектуры, подсказок и модели | нет формализации распределения ресурсов |
| *Self-Resource Allocation in Multi-Agent LLM Systems* | архитектуры Individual / Orchestrator / Planner | нет формальных критериев справедливого дележа |

## 2. Формальная модель

- `T = {t_1..t_N}` — подзадачи
- `A = {a_1..a_M}` — агенты
- `M = {m_1..m_K}` — LLM-модели
- **Кубик оценок**: `U ∈ [0,1]^(N×M×K)`, `U[i,j,k] = utility(t_i, a_j, m_k)` — предсказанная успешность тройки «подзадача–агент–модель»
- **Целевая функция**: максимизация `Σ U[i,j,k]` при ограничениях бюджета

## 3. Архитектура

```
GAIA-задача → Декомпозитор → [подзадачи] → Оракул → кубик U → Роутер → Агенты → результат
```

| Компонент | Реализация |
|---|---|

## 5. Справочник метрик

Обозначения: `U[i,j,k]` — кубик; распределение `D: i → (a(i), m(i))`; нагрузка агента
`L_j = Σ_{i: a(i)=j} U[i, j, m(i)]`; `n` — число агентов; `N` — число подзадач.

### Метрики из исходного кода

| Метрика | Формула | Диапазон | Смысл |
|---|---|---|---|
| `total_utility` | `Σ_i U[i, a(i), m(i)]` | [0, N] | суммарная предсказанная успешность; зависит от N, для сравнения нужен `avg_utility = /N` |
| `fairness_score` | `1 − (max_j L_j − min_j L_j) / Σ_j L_j` | (−∞, 1] | самодельная равномерность; 1 = все агенты равны |

Дефекты `fairness_score`: учитывает только крайних агентов, зависит от `n`, отсутствует в литературе по fair division → несопоставим с обзором. Оставлен только как мостик к старым прогонам.

### Добавленные метрики

**`usw` — Utilitarian Social Welfare.** `USW = Σ_j L_j`. Эффективность. Максимизируется независимым argmax по подзадаче, поэтому USW-роутер даёт верхнюю границу по этой метрике.

**`nsw` — Nash Social Welfare.** `NSW = (Π_j L_j)^(1/n)` — геометрическое среднее нагрузок. Обнуляется, если хотя бы один агент не получил ничего — это содержание метрики, а не дефект. Стандартный компромисс эффективности и справедливости; максимизация NSW в теории даёт Парето-оптимальность и EF1.

> Наблюдение: USW и NSW ранжируют роутеры в противоположном порядке. USW выигрывает +60% по эффективности и проигрывает в ~900 раз по NSW (0.178 против 0.916 у Round Robin). Это главный содержательный результат эксперимента.

**`gini` — коэффициент Джини по вектору нагрузок.** На отсортированных по возрастанию `L_(1) ≤ … ≤ L_(n)`:

```
G = 2·Σ_{r=1..n} (r · L_(r)) / (n · Σ_j L_j) − (n+1)/n
```

Диапазон `[0, 1 − 1/n]`; 0 = равенство, максимум = всё одному. Для n=3 максимум 0.667 — NSW-legacy показывает ровно это, что подтверждает полное вырождение. Описывает *форму* неравенства, дополняя NSW.

> При переходе к 10 агентам максимум станет 0.9 → числа перестанут быть сравнимыми. Либо печатать `n` рядом, либо нормировать: `G_norm = G · n/(n−1)`.

**`max_envy` — максимальная зависть.** Ценность чужого набора в глазах агента `j`: `v_j(S) = Σ_{i ∈ S} U[i, j, m(i)]`.

```
max_envy = max_{j, j'} [ v_j(S_j') − v_j(S_j) ]
```

`≤ 0` → распределение envy-free (EF). Ни одно из трёх распределений не является EF; «справедливый» по названию NSW-legacy — самый завистливый (3.697).

> при оценке чужого набора сохраняется модель, назначенная другому агенту. Альтернативное (более строгое) определение позволяет завидующему пересчитать набор под лучшую для себя модель: `v_j(S) = Σ_i max_k U[i,j,k]`. Выбран первый вариант, т.к. ресурс дискретен и модель прикреплена к задаче.

**`min_task_utility` = `min_i U[i, a(i), m(i)]`.** Самая плохо обслуженная подзадача — Rawlsian maximin на уровне задач. Критично именно для этой архитектуры: система является последовательным конвейером, цепочка не лучше слабейшего звена, а USW охотно обменивает провал одного шага на прирост по трём другим.

**`agent_load_counts` / `model_usage_counts`.** Счётчики подзадач (не полезность). Первый измеряет, используется ли специализация. Второй — монополизацию GPT-4 и картину cost/quality.

### Метрики которые стоит добавить

1. **Стоимость распределения** `Cost(D) = Σ_i cost(m(i))` и производная от неё **USW на доллар**. Сейчас вырождена: все пакеты по 0.001.
2. **Egalitarian welfare** `min_j L_j` — Rawlsian maximin на уровне агентов, цитируется в обзоре, но не измеряется.
3. **EF1 / EFX**: `v_j(S_j') − max_{i∈S_j'} v_j(i) ≤ v_j(S_j)`. Строгий EF при дискретных предметах обычно недостижим, стандарт в литературе — EF1.
4. **Регрет к точному оптимуму**: для 5×3×3 полный перебор `9^5 = 59 049` вариантов считается мгновенно. Без этого неизвестно, измеряется качество критерия или качество жадной эвристики.
5. **Price of Fairness** `PoF = (USW* − USW_fair) / USW*` — сколько эффективности стоит справедливость.
6. **Проверка Парето-доминирования** между распределениями разных роутеров.

## 6. Диагностика декомпозиции (10 задач GAIA, 74 подзадачи)

### Что лежит в Annotator Metadata

Каждая строка GAIA содержит `Question`, `Final answer`, `Level`, `file_name` и `Annotator Metadata` — JSON с полями `Steps`, `Number of steps`, `How long did this take?`, `Tools`, `Number of tools`. Поле `Steps` — пошаговая запись того, **как человек-аннотатор фактически решил задачу**. Создавалось авторами бенчмарка как свидетельство разрешимости, а не как вход для системы.

### Эталонный план и утечка разметки

Эталонный (gold) план — верифицированная человеком траектория, приведшая к правильному ответу. Утечка: в `Steps` закодированы источники, промежуточные величины, число и порядок шагов, иногда сами промежуточные значения. В реальном режиме на входе только `Question`.

Следствие: текущий протокол измеряет «насколько хорошо мы маршрутизируем идеальный план», а не «насколько хорошо система решает GAIA». Заявленная цель «точность на GAIA 30–40%» при таком протоколе недоказуема — система не решает задачи от начала до конца и не сверяется с `Final answer`.

При этом сам приём валиден: подача роутеру заведомо корректной декомпозиции — это **oracle decomposition ablation**, стандартный способ изолировать изучаемый компонент от шума соседнего. Дефект не в приёме, а в том, что он не назван и не имеет контрольного условия.

### Результат диагностики типизации

| Тип | По классификатору | Фактически |
|---|---|---|
| research | 30 (40.5%) | 30 (40.5%) |
| analysis | 37 (50.0%) | **5 (6.8%)** |
| *не распознано → fallback в analysis* | — | **32 (43.2%)** |
| coding | 4 (5.4%) | 4 (5.4%) |
| reasoning | 2 (2.7%) | 2 (2.7%) |
| summarization | 1 (1.4%) | 1 (1.4%) |

Профильность по матрице «роль × тип»: analyst 40 (54.1%), researcher 30 (40.5%), programmer 4 (5.4%).

### Два дефекта, вскрытые диагностикой

**1. Классификатор по ключевым словам недееспособен.** 43.2% шагов уходят в `ANALYSIS` по fallback → аналитик получает больше половины работы как наследник мусорной корзины. Дополнительно: правила проверяются по порядку, `ANALYSIS` идёт раньше `REASONING`, слово `evaluate` есть в обоих списках → `REASONING` почти никогда не срабатывает.

**2. Гранулярность шагов не соответствует понятию «подзадача».** Примеры нераспознанных шагов:

```
Go back to arxiv.org
Click result for the Nonindigenous Aquatic Species site.
Click "Marine Fishes"
Note that the tag for this category is "physics.soc-ph".
Note the results, which state that the main character is a clownfish.
```

Это отдельные действия в браузере и фиксация наблюдений — гранулярность лога действий человека (в среднем 7.4 шага на задачу, до 13), а не делегируемых заданий. Роутер назначает «Click "Marine Fishes"» аналитику с пакетом Claude-3 на 3000 токенов; ни один агент в системе физически не способен это выполнить, поскольку браузера у агентов нет.

**Следствие для порядка работ:** все метрики справедливости посчитаны на искажённой типизации. Сначала типизация и гранулярность, потом выводы про справедливость.

### Переформулировка проблемы для статьи

Вместо «специализация агентов не используется, программист получает 1% задач»:

> На задачах GAIA level 1–2 шаги аннотатора имеют гранулярность отдельных интерфейсных действий; доля подзадач, требующих программирования, составляет 5.4%, а 43.2% шагов не соответствуют ни одному типу интеллектуальной работы из априорной таксономии. Роль PROGRAMMER структурно невостребована не из-за свойств механизма распределения, а из-за несоответствия таксономии ролей фактическому составу подзадач. Состав агентов должен проектироваться по эмпирическому распределению типов подзадач.

## 7. Таксономия, которую диктуют данные

| Новый тип | Что ловит | Оценка доли | Профильная роль |
|---|---|---|---|
| `NAVIGATION` | go to, open, click, navigate, search | ~25% | `BROWSER` / `RETRIEVER` (нужен инструмент, модель дешёвая) |
| `EXTRACTION` | note, record, read the value, find the number | ~20% | `EXTRACTOR` (точность важнее рассуждения, дешёвая модель) |
| `RESEARCH` | find information, look up, gather | ~20% | `RESEARCHER` |
| `COMPUTATION` | calculate, count, sum, compare numbers | ~7% | `ANALYST` / `PROGRAMMER` |
| `CODING` | implement, script, parse file | ~5% | `PROGRAMMER` |
| `REASONING` | deduce, infer, decide which | ~3% | `REASONER` (дорогая модель оправдана) |
| `VERIFICATION` | check, cross-reference, confirm | ~3% | `CRITIC` |
| `SUMMARIZATION` | report, format the answer | ~2% | `WRITER` |

Ключевой выигрыш: `NAVIGATION` + `EXTRACTION` ≈ 45% работы, и им не нужна дорогая модель. Здесь появляется настоящий cost/quality trade-off, которого сейчас нет из-за равных цен пакетов. Монополия GPT-4 (97.3%) должна разрушиться на этой таксономии — измеримый результат вместо декларации.

Классификатор заменить с ключевых слов на LLM-классификатор при T=0 с фиксированной схемой вывода; качество мерить против ручной разметки ~50 шагов (согласие по каппе Коэна). Keyword-вариант оставить дешёвым baseline для сравнения.

| # | Дефект | Статус |
|---|---|---|

| 7 | Эвристика сжимает шкалу: `score = 0.5·role·model` даёт максимум ≈0.4 для коротких задач | пересмотреть формулу вместе с новой таксономией |

## 9. План работ

### Ближайший блок

1. **Новая таксономия типов + LLM-классификатор.** Замер согласия с ручной разметкой (~50 шагов) и со старым keyword-классификатором. От этого пункта зависят 2 и 3.
2. **Расширенный состав агентов.** 7 ролей, матрицы совместимости под новую таксономию, 4–5 моделей разной цены.
3. **Реальные цены пакетов** вместо `cost=0.001`. Без этого cost/quality не измерить.
4. **Доработка роутеров и метрик.** Свип по `fairness_weight`; точный оптимум перебором; регрет; Price of Fairness; egalitarian welfare; EF1.
5. **Условие B — автономная декомпозиция.** LLM-декомпозитор на уровне содержательных подзадач (3–5 на задачу), сравнение с эталонной декомпозицией. Разница `A − B` — цена несовершенной декомпозиции, отдельный результат.
6. **Стабильность только по LLM-клеткам.**

### Из плана развития презентации

- Обучение оракула на данных для повышения стабильности оценок
- Масштабирование до 10+ агентов и 5+ моделей, параллельное выполнение независимых подзадач
- Доказательство существования равновесий для пакетов равной стоимости
- Снижение стоимости решений на 40–60% против использования GPT-4 для всего
- Подготовка публикации
